How it works
1
One ingress for every platform
Every event — new GHL lead, Stripe payment, WhatsApp inbound, Google Calendar change — hits a single webhook gateway that normalizes the payload, authenticates the source, and routes to the right routine. Add a new platform in config.yaml, not in code.
2
Claude Code decides, doesn't just transform
The Routine Registry tells Claude which playbook to run per tenant. Claude reads the event + config, makes the decision (onboard this user? upsell? escalate? sync?), personalizes the output, and emits a structured action plan — no hardcoded if/else trees.
3
Execute through a hardened API layer
One shared integration library handles OAuth refresh, rate limits, idempotency keys, and exponential retries for every downstream API. Claude emits intent; the layer handles the messy reality of Stripe 429s, GHL timeouts, and WhatsApp quota.
4
Run the four core operations
Onboarding (provision accounts, send welcome, configure CRM), CRM syncing (keep GHL ↔ Stripe ↔ internal DB consistent), Reporting (scheduled digests to Slack / email), and Internal Ops (billing reconciliation, churn alerts, audit exports).
5
Observability by default
Every routine emits structured traces — who triggered what, which API calls fired, latency, outcome. Failures and anomalies page the admin via Slack or PagerDuty immediately; the rest goes to a searchable audit log. No silent failures, no "it worked on my machine."
